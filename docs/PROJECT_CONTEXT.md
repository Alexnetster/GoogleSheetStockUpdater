# 프로젝트 컨텍스트: Google Sheet Stock Updater

## 1. 프로젝트 개요 (Overview)
이 프로젝트는 **구글 시트(Google Sheets)를 메인 UI로 사용하는 자동화된 주식 & 코인 추적 시스템**입니다.
*   **사용자**: 모바일 구글 시트 앱에서 관심 종목(주식, 코인)과 알림 설정을 직접 관리합니다.
*   **시스템**: GitHub Actions에서 실행되는 파이썬 백엔드가 이 설정을 읽고, 실시간 데이터(야후 파이낸스, 네이버 증권 등)를 수집하여 시트에 결과를 갱신합니다.
*   **목표**: 별도의 앱 개발 없이 "모바일 앱 같은 사용자 경험"을 제공하며, 고성능과 신뢰성을 확보하는 것입니다.

## 2. 핵심 아키텍처: "하이브리드 모델"
이 시스템은 철저하게 **"시트는 UI다"** 라는 철학을 따릅니다.
*   **UI 계층 (구글 시트)**:
    *   **입력**: `Config` 탭 (사용자가 드롭다운으로 모니터링 여부, 알림 설정).
    *   **출력**: `Stocks`, `Dashboard` 탭 (파이썬이 분석한 결과를 보여줌).
    *   **로직**: 없음. 시트는 복잡한 수식 없이 껍데기 역할만 합니다.
*   **백엔드 계층 (파이썬)**:
    *   **역할**: 두뇌. 모든 데이터 수집, 분석, 포맷팅을 담당합니다.
    *   **구조**: 모듈화된 아키텍처 (Adapters, Domain, Services).
    *   **실행**: GitHub Actions (Cron 스케줄러) 또는 수동 트리거.

## 3. 기술적 제약 및 원칙
*   **성능 (Performance)**:
    *   **비동기(Async) 필수**: 실행 시간을 최소화하기 위해 데이터 수집 시 `asyncio`와 `aiohttp` 사용이 필수입니다.
    *   **배치 처리**: 모든 시트 API 호출은 `batchGet`과 `batchUpdate`를 사용해야 합니다.
*   **데이터 정합성**:
    *   **하이브리드 소스**:
        *   **미국 주식**: 야후 파이낸스 (`yfinance`).
        *   **한국 주식**: 네이버 증권 (크롤링).
        *   **코인**: 야후 파이낸스 또는 전용 API.
*   **코드 품질**:
    *   **타입 힌트**: 모든 새로운 코드에 필수 적용.
    *   **테스트**: `pytest` 표준 사용. 로직은 API 호출과 분리되어 테스트 가능해야 합니다.

## 4. 진행 상황 (로드맵 1단계)
현재 거대한 단일 스크립트(`updater.py`)를 깔끔한 모듈 구조로 **리팩토링**하는 중입니다.
*   **현재 우선순위**: API 로직(Adapters)과 비즈니스 로직 분리.
*   **다음 우선순위**: 비동기 I/O 도입으로 5배 이상의 속도 향상.
