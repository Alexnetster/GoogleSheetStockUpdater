# 이걸 antigravity에게 어떻게 효과적으로 잔달할 수 있을까? 파일?

## 프로젝트 개요
<overview>
Google Sheets를 설정 인터페이스로 사용하는 자동화된 주식/코인 트레이딩 데이터 파이프라인.
모바일에서 쉽게 설정 변경 가능하며, GitHub Actions cron으로 자동 실행.
</overview>

## 핵심 요구사항
<requirements>
1. **모바일 친화성**: Google Sheets로 언제 어디서나 설정 수정
2. **성능**: 현재 느린 속도를 개선 (목표: 5분 이내 완료)
3. **정확성**: 금융 데이터의 정합성 보장
4. **확장성**: 새로운 API/지표 추가가 용이한 구조
5. **신뢰성**: 테스트 자동화로 회귀 방지
</requirements>

## 기술 스택
<tech_stack>
- **Language**: Python 3.11+
- **APIs**: 
  - Google Sheets API (설정 읽기/결과 쓰기)
  - 네이버증권 API (한국 주식)
  - Crypto APIs (코인 가격)
  - Google Calendar API (이벤트 생성)
- **Infrastructure**: GitHub Actions (cron 실행)
- **Testing**: pytest, pytest-benchmark
- **Async**: asyncio, aiohttp
</tech_stack>

## 현재 문제점
<issues>
1. 순차적 API 호출로 인한 속도 저하 (예상: 10-15분 소요)
2. 개별 Sheets 업데이트로 인한 API 호출 과다

<optimization_goals>

2. Batch 요청으로 Sheets API 호출 최소화
3. 캐싱으로 불필요한 API 호출 제거
4. 실행 시간 목표: 5분 이내
</optimization_goals>

## 아키텍처 원칙
<architecture_principles>
1. **Sheets는 UI**: Google Sheets는 설정/결과 인터페이스로만 사용
2. **로직 분리**: 비즈니스 로직은 Python에서 테스트 가능하게 작성
3. **어댑터 패턴**: 외부 API는 어댑터로 추상화
4. **테스트 우선**: 핵심 로직은 단위 테스트, 통합은 E2E 테스트
5. **성능 모니터링**: 모든 주요 함수의 실행 시간 측정
</architecture_principles>

- [시스템 아키텍처](./ARCHITECTURE.md)

## 3. OPTIMIZATION_GUIDE.md

```markdown
# Performance Optimization Guide

## 1. 비동기 API 호출
<async_pattern>
**Before (순차)**: 850ms × 3종목 = 2550ms
```python
results = []
for symbol in symbols:
    data = requests.get(f'https://api.../stock/{symbol}').json()
    results.append(data)
```

**After (병렬)**: 850ms / 3 = ~283ms

```python
async def fetch_all():
    async with aiohttp.ClientSession() as session:
        tasks = [fetch_one(session, symbol) for symbol in symbols]
        return await asyncio.gather(*tasks)
```

</async_pattern>

## 2. Sheets API 배치 요청

<batch_pattern>
**Before (개별)**: 10 API 호출

```python
for sheet in sheets:
    service.spreadsheets().values().update(
        spreadsheetId=id, range=sheet, body=data
    ).execute()
```

**After (배치)**: 1 API 호출

```python
requests_body = {
    'data': [
        {'range': sheet, 'values': data} 
        for sheet, data in updates.items()
    ],
    'valueInputOption': 'RAW'
}
service.spreadsheets().values().batchUpdate(
    spreadsheetId=id, body=requests_body
).execute()
```

</batch_pattern>

## 3. 캐싱 전략

<caching>
- **종목 리스트**: 1시간 캐시 (자주 안 바뀜)
- **가격 데이터**: 5분 캐시 (실시간성 필요)
- **기술적 지표**: 계산 결과 메모이제이션
</caching>

## 4. Rate Limit 관리

<rate_limiting>

- Google Sheets: 100초당 100회 → 배치로 10배 효율
- 네이버증권: Semaphore로 동시 요청 5개 제한
- 재시도: Exponential backoff (1s, 2s, 4s, 8s)
</rate_limiting>

# Trading Automation Project Rules

## 코딩 스타일

- Python 3.11+ 타입 힌트 필수 사용
- async/await 패턴 우선 (I/O bound 작업)
- 함수는 단일 책임 원칙 준수
- 100자 이하 라인 길이


## 아키텍처 원칙

- 외부 API는 반드시 adapters/ 에 어댑터 클래스로 추상화
- 비즈니스 로직은 domain/ 에 순수 함수로 작성
- Google Sheets는 설정 읽기/결과 쓰기만 사용 (계산 로직 X)


## 성능 최적화

- API 호출은 asyncio.gather로 병렬화
- Sheets API는 batchGet/batchUpdate 사용
- 자주 조회하는 데이터는 캐싱 (utils/cache.py)


## 테스트 요구사항

- 새로운 함수 작성 시 단위 테스트 필수 동반
- API 호출은 pytest.fixture로 모킹
- 성능 중요 함수는 pytest-benchmark 추가


## 금융 데이터 검증

- 가격 데이터는 0 이상 체크
- 날짜/시간 필드는 ISO 8601 포맷
- 종목 코드는 중복 제거 후 처리


## 에러 처리

- API 호출 실패 시 재시도 로직 (exponential backoff)
- 중요 에러는 Sentry로 전송
- 사용자 친화적 에러 메시지 (Sheets에 기록)


## 파일 참조

- 전체 구조는 docs/PROJECT_CONTEXT.md 참조
- API 명세는 docs/API_SPECS.md 참조
- 최적화 패턴은 docs/OPTIMIZATION_GUIDE.md 참조
