# 그런데 구글독스에 요청 시트를 추가한 것은 외부에서 모바일 같은 장치로도 요청을 쉽게 수정하려고 한건데.. 너가 알려준 방식도 쉽게 대응할수 있는거야?

**완전히 대응 가능합니다!** 오히려 Google Sheets를 모바일에서 설정을 수정하는 인터페이스로 사용하는 것은 **매우 현명한 선택**입니다 [^1][^2]. 제가 제안한 테스트 및 최적화 구조는 백엔드 로직에만 적용하고, Sheets는 그대로 "프론트엔드 UI"로 유지하면 됩니다 [^3][^4].

## 하이브리드 아키텍처: Sheets as UI + Python as Backend

Google Sheets를 모바일 친화적인 설정 인터페이스로 유지하면서 성능을 최적화하는 구조입니다.

### 설정 시트 구조 예시

```
📊 Google Sheets 구조:
┣━ 📄 Config (설정 시트)
┃   ┣ 종목코드 | 종목명 | 모니터링 | 알림설정 | 갱신주기
┃   ┣ 005930  | 삼성전자 | TRUE    | BUY신호  | 5분
┃   └ 000660  | SK하이닉스 | TRUE  | SELL신호 | 5분
┃
┣━ 📄 Indicators (지표 설정)
┃   ┣ 지표명    | 파라미터1 | 파라미터2 | 활성화
┃   ┣ 볼린저밴드 | 20       | 2        | TRUE
┃   └ RSI      | 14       | -        | TRUE
┃
┣━ 📄 Calendar (캘린더 이벤트 설정)
┃   ┣ 이벤트타입 | 생성여부 | 알림시간
┃   └ 매수신호   | TRUE    | 15분전
┃
┣━ 📄 Stocks (결과 - 자동 갱신)
┣━ 📄 Signals (신호 - 자동 갱신)
└━ 📄 Performance (성능 로그 - 자동 갱신)
```

모바일에서 `Config`와 `Indicators` 시트만 수정하면 되고, 나머지는 Python이 자동으로 처리합니다 [^2][^4].

### Python 코드는 설정을 읽기만 함

```python
# src/adapters/google_sheets.py
class ConfigSheetAdapter:
    def __init__(self, service, spreadsheet_id):
        self.service = service
        self.spreadsheet_id = spreadsheet_id
    
    def read_config(self) -> dict:
        """설정 시트에서 사용자 설정 읽기"""
        result = self.service.spreadsheets().values().batchGet(
            spreadsheetId=self.spreadsheet_id,
            ranges=['Config!A2:E', 'Indicators!A2:D', 'Calendar!A2:C']
        ).execute()
        
        # 설정 파싱
        config = {
            'stocks': self._parse_stocks(result['valueRanges'][^0]),
            'indicators': self._parse_indicators(result['valueRanges'][^1]),
            'calendar': self._parse_calendar(result['valueRanges'][^2])
        }
        return config
    
    def _parse_stocks(self, value_range) -> list:
        """종목 설정 파싱"""
        stocks = []
        for row in value_range.get('values', []):
            if len(row) >= 5 and row[^2].upper() == 'TRUE':  # 모니터링 활성화된 것만
                stocks.append({
                    'code': row[^0],
                    'name': row[^1],
                    'alert_type': row[^3],
                    'interval': row[^4]
                })
        return stocks

# src/main.py
def run_pipeline():
    # 1. 설정 읽기 (Sheets에서)
    config_adapter = ConfigSheetAdapter(service, SPREADSHEET_ID)
    config = config_adapter.read_config()
    
    # 2. 비즈니스 로직 실행 (여기에 테스트 적용)
    pipeline = DataPipeline(config)
    results = await pipeline.execute()
    
    # 3. 결과를 다시 Sheets에 쓰기
    result_adapter = ResultSheetAdapter(service, SPREADSHEET_ID)
    await result_adapter.update_results(results)
```

이렇게 하면 **설정은 모바일로, 로직은 테스트 코드로** 각각 관리할 수 있습니다 [^3][^5].

## 모바일 친화적인 Sheets UI 개선

### 1. 드롭다운과 체크박스 활용

모바일에서 직접 타이핑하는 대신 드롭다운으로 선택하게 하면 편리합니다 [^6][^7].

**설정 방법 (모바일에서도 가능):**

1. 설정할 셀 선택
2. 우측 상단 점 3개 메뉴 → "데이터 유효성 검사"
3. 기준: "목록(범위 내)" 또는 "목록(항목 직접)"
4. 항목 입력: `TRUE, FALSE` 또는 `BUY신호, SELL신호, 전체알림`
```
Config 시트 데이터 유효성 검사:
- 모니터링 열(C): TRUE, FALSE (드롭다운)
- 알림설정 열(D): BUY신호, SELL신호, 전체알림, 알림없음
- 갱신주기 열(E): 1분, 5분, 15분, 1시간
```

이렇게 하면 모바일에서 탭 몇 번으로 설정을 바꿀 수 있습니다 [^6].

### 2. 모바일 전용 "대시보드" 탭 추가

복잡한 데이터는 보기 어려우니 모바일용 요약 탭을 만듭니다 [^2].

```python
# src/adapters/mobile_dashboard.py
def create_mobile_dashboard(service, spreadsheet_id, data):
    """모바일 친화적인 대시보드 생성"""
    dashboard_data = [
        ['📊 트레이딩 대시보드'],
        [''],
        ['⏰ 마지막 업데이트', data['last_update']],
        ['✅ 처리된 종목 수', str(data['processed_stocks'])],
        ['⚡ 실행 시간', f"{data['execution_time']:.1f}초"],
        [''],
        ['🔥 최근 신호'],
    ]
    
    # 최근 신호 5개만 표시
    for signal in data['recent_signals'][:5]:
        dashboard_data.append([
            signal['timestamp'],
            signal['symbol'],
            signal['type'],
            signal['price']
        ])
    
    # 큰 폰트, 명확한 구분
    requests = [{
        'updateCells': {
            'range': {'sheetId': get_sheet_id('Dashboard')},
            'rows': [{'values': [{'userEnteredValue': {'stringValue': cell}} 
                                 for cell in row]} 
                     for row in dashboard_data],
            'fields': 'userEnteredValue'
        }
    }, {
        'repeatCell': {
            'range': {'sheetId': get_sheet_id('Dashboard'), 'startRowIndex': 0, 'endRowIndex': 1},
            'cell': {'userEnteredFormat': {'textFormat': {'fontSize': 16, 'bold': True}}},
            'fields': 'userEnteredFormat.textFormat'
        }
    }]
    
    service.spreadsheets().batchUpdate(
        spreadsheetId=spreadsheet_id,
        body={'requests': requests}
    ).execute()
```

모바일에서는 `Dashboard` 탭만 보면 전체 상황을 파악할 수 있습니다 [^2].

### 3. 버튼으로 즉시 실행 (Apps Script)

GitHub Actions의 cron을 기다리지 않고, 모바일에서 버튼 터치로 즉시 실행할 수 있습니다 [^8][^3].

```javascript
// Google Sheets의 확장 프로그램 > Apps Script
function onOpen() {
  const ui = SpreadsheetApp.getUi();
  ui.createMenu('🔄 트레이딩 봇')
    .addItem('📈 지금 데이터 갱신', 'triggerPipeline')
    .addItem('🧪 테스트 실행', 'testPipeline')
    .addItem('📊 성능 리포트', 'showPerformance')
    .addToUi();
}

function triggerPipeline() {
  // GitHub Actions workflow를 수동으로 트리거
  const url = 'https://api.github.com/repos/<username>/<repo>/actions/workflows/<workflow_id>/dispatches';
  const options = {
    'method': 'post',
    'headers': {
      'Authorization': 'token ' + PropertiesService.getScriptProperties().getProperty('GITHUB_TOKEN'),
      'Accept': 'application/vnd.github.v3+json'
    },
    'payload': JSON.stringify({'ref': 'main'})
  };
  
  UrlFetchApp.fetch(url, options);
  SpreadsheetApp.getUi().alert('✅ 데이터 갱신을 시작했습니다!');
}

// 또는 Python 서버에 직접 webhook 호출
function triggerPipelineWebhook() {
  const webhookUrl = PropertiesService.getScriptProperties().getProperty('PIPELINE_WEBHOOK');
  const config = SpreadsheetApp.getActiveSpreadsheet().getSheetByName('Config').getDataRange().getValues();
  
  const options = {
    'method': 'post',
    'contentType': 'application/json',
    'payload': JSON.stringify({
      'trigger': 'manual',
      'spreadsheet_id': SpreadsheetApp.getActiveSpreadsheet().getId(),
      'config': config
    })
  };
  
  UrlFetchApp.fetch(webhookUrl, options);
}
```

이제 모바일 Sheets 앱에서 **메뉴 → 트레이딩 봇 → 지금 데이터 갱신**을 탭하면 즉시 실행됩니다 [^8][^3].

## 테스트는 백엔드 로직에만 적용

Sheets 설정 읽기/쓰기는 모킹하고, 비즈니스 로직만 테스트합니다.

```python
# tests/unit/test_data_pipeline.py
import pytest
from unittest.mock import Mock
from src.services.data_pipeline import DataPipeline

@pytest.fixture
def mock_config():
    """실제 Sheets 대신 모킹된 설정"""
    return {
        'stocks': [
            {'code': '005930', 'name': '삼성전자', 'alert_type': 'BUY신호', 'interval': '5분'}
        ],
        'indicators': [
            {'name': '볼린저밴드', 'param1': 20, 'param2': 2, 'enabled': True}
        ]
    }

def test_pipeline_processes_stocks_correctly(mock_config):
    """파이프라인이 설정대로 처리하는지 테스트"""
    pipeline = DataPipeline(mock_config)
    results = pipeline.execute()
    
    assert len(results['stocks']) == 1
    assert results['stocks'][^0]['code'] == '005930'
    assert 'bollinger_bands' in results['stocks'][^0]['indicators']
```

**실제 Sheets 연동은 통합 테스트에서만:**


## 실제 워크플로우

### 1. 모바일에서 설정 변경

- Google Sheets 앱 열기
- `Config` 시트에서 종목 추가/삭제 또는 드롭다운으로 옵션 변경
- 자동 저장됨 ✅


### 2. 자동 실행 (Cron)

```yaml
# .github/workflows/cron.yml
on:
  schedule:
    - cron: '0 9,15 * * 1-5'  # 평일 18시, 00시 (KST)

jobs:
  run:
    steps:
      - name: Run Pipeline
        run: python src/main.py
        # → Sheets에서 최신 설정 읽음
        # → 처리 후 결과를 Sheets에 씀
```


### 3. 수동 실행 (모바일에서 즉시)

- Sheets 앱에서 **메뉴 → 트레이딩 봇 → 지금 갱신**
- 또는 GitHub Actions에서 "Run workflow" 버튼


### 4. 결과 확인 (모바일에서)

- `Dashboard` 탭: 요약 정보
- `Stocks` 탭: 전체 상세 데이터
- `Performance` 탭: 실행 시간 로그


## 더 편리한 모바일 경험을 위한 추가 옵션

### Glide/AppSheet로 네이티브 앱처럼 만들기

Google Sheets를 백엔드로 사용하되, UI만 모바일 앱처럼 만들 수 있습니다 [^9][^1][^10].

- **Glide** (무료 플랜 가능): Sheets를 드래그 앤 드롭으로 앱 UI로 변환
- **AppSheet** (Google 공식): 더 복잡한 로직과 자동화 가능 [^11]

이렇게 하면:

- 📱 모바일 앱처럼 보이는 UI
- 📊 백엔드는 여전히 Google Sheets
- 🔄 Python 코드는 그대로 Sheets API 사용

**하지만 대부분의 경우 Google Sheets 모바일 앱만으로 충분합니다** [^2][^12].

## 정리: 둘 다 잡는 구조

```
📱 모바일 (Google Sheets 앱)
   ↓ 설정 수정 (드롭다운, 체크박스)
   ↓
📊 Google Sheets (설정 저장소)
   ↓ API 읽기
   ↓
🐍 Python 백엔드
   ├─ 설정 읽기 (Sheets API)
   ├─ 비즈니스 로직 실행 ← ✅ 여기에 테스트 적용
   ├─ 성능 최적화 (async, batch) ← ✅ 벤치마크 적용
   └─ 결과 쓰기 (Sheets API)
   ↓
📊 Google Sheets (결과 저장소)
   ↓ 모바일에서 확인
   ↓
📱 모바일 (결과 확인, Dashboard 탭)
```

**이 구조의 장점:**

- ✅ 모바일에서 쉽게 설정 변경 (원래 의도 유지)
- ✅ Python 로직은 테스트로 검증 (품질 보장)
- ✅ 성능 최적화 적용 (속도 개선)
- ✅ 기능 추가 시 코드만 수정, Sheets 구조는 유지
- ✅ 버전 관리는 Python 코드만, 설정은 Sheets에

따라서 **지금 사용 중인 방식을 그대로 유지하면서**, 백엔드 코드에만 제가 제안한 테스트/최적화를 적용하면 완벽하게 양립할 수 있습니다 [^3][^4]!
