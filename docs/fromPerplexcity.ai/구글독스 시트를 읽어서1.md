# 구글독스 시트를 읽어서 시트내용을 갱신하고 다른 파이낸셜 api와 네이버증권 api에 증권과 코인 정보를 읽어서 이정보를 구글독스 탭에 여러 형태로 생성 또는 갱신하고 각종 탭에 내용을 생성하고 캘린더 api로 캘린더 정보를 생성하도록 python으로 작성했고, 이것을 git hub 의 actions에서 cron 으로 실행하도록 했는데 속도가 늦어... 속도를 높일 방안이 뭐가 있을까?

Google Sheets와 여러 API를 활용한 자동화 스크립트의 속도를 개선할 수 있는 여러 방법이 있습니다 [^1][^2][^3]. GitHub Actions에서 실행되는 Python 스크립트의 성능 최적화는 비용 절감과 실행 시간 단축에 직접적인 영향을 미칩니다 [^4].

## Google Sheets API 배치 요청 활용

가장 효과적인 최적화 방법은 개별 API 호출을 배치 요청으로 통합하는 것입니다 [^1][^5]. `spreadsheets.values.batchGet`과 `spreadsheets.values.batchUpdate`를 사용하면 여러 범위의 데이터를 단일 호출로 읽고 쓸 수 있습니다 [^6].

```python
# 기존: 여러 번 호출
for sheet in sheets:
    result = service.spreadsheets().values().get(
        spreadsheetId=spreadsheet_id, range=sheet
    ).execute()

# 개선: 배치 요청
batch_ranges = ['Sheet1!A1:Z100', 'Sheet2!A1:Z100', 'Sheet3!A1:Z100']
result = service.spreadsheets().values().batchGet(
    spreadsheetId=spreadsheet_id,
    ranges=batch_ranges
).execute()
```

배치 업데이트의 경우 `batchUpdate` 메서드를 사용하여 여러 시트의 데이터를 한 번에 갱신할 수 있습니다 [^5]. Google Sheets API는 100초당 500회의 읽기/쓰기 제한이 있으므로, 배치 요청을 사용하면 rate limit 내에서 더 많은 작업을 처리할 수 있습니다 [^6][^7].

## 비동기 처리로 병렬 API 호출

네이버증권 API, 금융 API, 캘린더 API 등 여러 외부 API를 호출할 때는 `asyncio`와 `aiohttp`를 사용한 비동기 처리가 핵심입니다 [^8][^9]. 동기 방식의 `requests` 라이브러리 대신 비동기 방식을 사용하면 I/O 대기 시간 동안 다른 작업을 처리할 수 있어 전체 실행 시간을 크게 단축할 수 있습니다 [^10].

```python
import asyncio
import aiohttp

async def fetch_stock_data(session, symbol):
    async with session.get(f'https://api.example.com/stock/{symbol}') as response:
        return await response.json()

async def fetch_all_stocks(symbols):
    async with aiohttp.ClientSession() as session:
        tasks = [fetch_stock_data(session, symbol) for symbol in symbols]
        results = await asyncio.gather(*tasks)
        return results

# 7개 항목을 순차 처리: 6.17초 → 비동기 처리: 0.85초
symbols = ['005930', '000660', '035420']
results = asyncio.run(fetch_all_stocks(symbols))
```

비동기 처리는 순차 처리 대비 약 7배 이상의 성능 향상을 제공합니다 [^10]. 다만 API rate limit이 있는 경우 `asyncio.Semaphore`로 동시 요청 수를 제한해야 합니다 [^11].

## ThreadPoolExecutor를 활용한 병렬 처리

Google Sheets API는 현재 비동기를 직접 지원하지 않으므로, `concurrent.futures.ThreadPoolExecutor`를 사용한 병렬 처리가 효과적입니다 [^12][^13]. I/O bound 작업의 경우 GIL의 영향을 적게 받아 멀티스레드가 효율적으로 동작합니다 [^12].

```python
from concurrent.futures import ThreadPoolExecutor
import requests

def update_sheet_tab(tab_name, data):
    # Google Sheets API 호출
    service.spreadsheets().values().update(
        spreadsheetId=spreadsheet_id,
        range=tab_name,
        body={'values': data}
    ).execute()

# 여러 탭을 병렬로 업데이트
with ThreadPoolExecutor(max_workers=5) as executor:
    futures = [
        executor.submit(update_sheet_tab, tab, data) 
        for tab, data in tab_data_pairs
    ]
    results = [f.result() for f in futures]
```


## GitHub Actions 최적화

### 의존성 캐싱

GitHub Actions에서 Python 의존성을 캐싱하면 매번 패키지를 다운로드하는 시간을 절약할 수 있습니다 [^14][^4].

```yaml
- name: Cache pip dependencies
  uses: actions/cache@v3
  with:
    path: ~/.cache/pip
    key: ${{ runner.os }}-pip-${{ hashFiles('**/requirements.txt') }}
    restore-keys: |
      ${{ runner.os }}-pip-
```


### 데이터 캐싱 전략

변경 빈도가 낮은 데이터는 GitHub Actions 캐시나 아티팩트에 저장하여 재사용할 수 있습니다 [^15]. 예를 들어 종목 리스트, 기본 설정 등은 매번 가져오는 대신 캐시에서 로드하는 방식으로 개선할 수 있습니다.

## 로컬 데이터 캐싱

자주 조회하지만 자주 변경되지 않는 데이터는 로컬에 캐싱하여 불필요한 API 호출을 줄일 수 있습니다 [^3]. Redis나 간단한 파일 기반 캐싱을 활용할 수 있습니다.

```python
import pickle
from datetime import datetime, timedelta

def get_cached_data(cache_key, fetch_func, cache_duration_minutes=30):
    cache_file = f'cache_{cache_key}.pkl'
    
    if os.path.exists(cache_file):
        with open(cache_file, 'rb') as f:
            cached = pickle.load(f)
            if datetime.now() - cached['timestamp'] < timedelta(minutes=cache_duration_minutes):
                return cached['data']
    
    data = fetch_func()
    with open(cache_file, 'wb') as f:
        pickle.dump({'timestamp': datetime.now(), 'data': data}, f)
    
    return data
```


## API Rate Limit 관리

Google Sheets API는 프로젝트당 분당 300회, 사용자당 100초당 100회의 제한이 있습니다 [^7]. Exponential backoff를 구현하여 rate limit 오류 시 재시도 로직을 추가하면 안정성이 향상됩니다 [^3].

```python
import time
from googleapiclient.errors import HttpError

def api_call_with_retry(func, max_retries=5):
    for i in range(max_retries):
        try:
            return func()
        except HttpError as e:
            if e.resp.status == 429:  # Rate limit
                wait_time = (2 ** i) + random.random()
                time.sleep(wait_time)
            else:
                raise
    raise Exception("Max retries exceeded")
```


## 추가 최적화 팁

- **필드 선택자 사용**: API 응답에서 필요한 필드만 요청하여 데이터 전송량을 줄입니다 [^3]
- **증분 업데이트**: 전체 데이터를 매번 갱신하는 대신 변경된 부분만 업데이트합니다
- **압축 전송**: API 요청 시 gzip 압축을 활성화하여 네트워크 전송 시간을 단축합니다

이러한 최적화 방법들을 조합하면 실행 시간을 수 분에서 수십 초로 단축할 수 있습니다 [^14][^10].
